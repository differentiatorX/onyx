Payments break in eight ways.

Most projects only handle the happy path. Onyx was built around the failures, and ships a deliberately unreliable mock bank so you can trigger each one yourself.

From checkout to payout.

One payment, start to finish. Each step commits as a single database transaction, so nothing ever lands halfway.

1

Create

Your server asks for a payment with an Idempotency-Key. Risk rules score it before anything else happens.

2

Pay

The customer pays on hosted checkout through Razorpay or the mock bank. Signed webhooks report the result.

3

Book

The capture, its ledger entry and your webhook event commit together. Workers deliver the webhook with retries.

4

Settle

The provider pays the platform, the platform pays you, and reconciliation checks it all against the bank.

Retry anything. Safely.

Send the same request ten times and Onyx creates one payment. The bundled SDK retries for you, so a flaky network is never your problem.

  • Amounts are integers in paise, end to end
  • Webhooks signed with HMAC-SHA256 and a timestamp to block replays
  • Rate limits per key, enforced atomically in Redis
  • Cursor pagination, typed errors and a zero-dependency Node SDK
# Create a payment. Retrying with the same key is safe.
curl localhost:4000/v1/payments \
  -H "Authorization: Bearer sk_test_..." \
  -H "Idempotency-Key: order-1042" \
  -d '{"amount": 49900,
       "customer": {"email": "riya@example.com"}}'
